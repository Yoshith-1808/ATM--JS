Crease 04 Engineering Notes
Philosophy

How I approach software engineering.

1. Clean Boundaries Make Fast Systems +

I treat backend services as long-term investments. When applications grow into many services, speed comes from clear, clean boundaries.

By using stateless JWT security, fixing slow database queries before code gets merged, and sticking to the Controller-Service-Repository pattern, I make sure systems stay fast and predictable even under heavy traffic.

Reaching zero authentication bugs in production isn't luck—it comes from thorough unit tests with Mockito, clear API contracts, and careful input checks.

2. Core Engineering Principles +
Explicit Contracts

Clear DTO objects keep internal database tables separate from API payloads, preventing breaking changes.

Stateless Design

Removing server-side sessions lets services scale up immediately across cloud servers.

Defensive Validation

Consistent error responses keep internal errors hidden from the outside while giving clear guidance to frontends.

Two-Week Sprints

Agile cycles backed by Git branching and automated test suites help ship features reliably on schedule.

3. How I Cut API Latency by 40% +

During the Revature project, performance profiling revealed that nested database queries and unindexed foreign keys were slowing down responses.

By creating composite indexes for the most common search patterns and switching to efficient JPQL queries, we cut average API response time by about 40% under heavy test and live user loads.
